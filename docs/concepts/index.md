## Category: Families

Families of actors and the units that run them.

| Term | Meaning | Read more |
|---|---|---|
| <a id="family"></a>**family** | One of the four groups every actor belongs to: work, data, keys or audit. A port is never shared between two families.<br>*Avoid:* layer (for a family); tier. | [ADR 0002](/decisions/0002-families-of-actors/#the-four-families), [Families](/concepts/families/) |
| <a id="work-actor"></a>**work actor** | An actor that does one job of sluis (entry, console, session, exchange, policy, signer, ca, ssh-ca (a separate actor from ca), quota, or an adapter). It holds no storage, key or audit credential at rest; it reaches data, keys and audit only through its ports.<br>*Avoid:* role; process role; service (for an actor). | [ADR 0002](/decisions/0002-families-of-actors/#work-actors) |
| <a id="actor"></a>**actor** | A program with one responsibility, run as its own unit in each boundary it serves. Every actor belongs to one family.<br>*Avoid:* role; process role; component (for an actor). | [ADR 0002](/decisions/0002-families-of-actors/) |
| <a id="actor-boundary"></a>**actor@boundary** `<actor>@<boundary>` | The name of one actor in one boundary, for example `session@prod` or `store@prod`. The same name appears in every layer that enforces it: unit, user, socket, function, service account, key alias and the actor field of an audit record.<br>*Avoid:* actor instance (as a separate term).<br>*Note:* Also written for holders: store@boundary, key@boundary, exporter@boundary. In prose, `store@`, `key@` and `exporter@` mean the holder of the boundary being discussed. | [ADR 0002](/decisions/0002-families-of-actors/#names) |
| <a id="credential-holder"></a>**credential holder** | A unit that holds a credential at rest. There are exactly four kinds: store@ and exporter@ (data), key@ (keys), and the audit pieces that hold a credential (writer, witness, indexer, reader). No work actor is one.<br>*Avoid:* mediator; mediating driver; state-owner; key-holder. | [ADR 0002](/decisions/0002-families-of-actors/#credential-holders) |
| <a id="data-family"></a>**data family** | store@ and exporter@: the only units that hold storage or export-destination credentials. | [ADR 0002](/decisions/0002-families-of-actors/#the-four-families) |
| <a id="keys-family"></a>**keys family** | key@: the only unit that holds a card PIN or a KMS permission. | [ADR 0002](/decisions/0002-families-of-actors/#the-four-families), [ADR 0006](/decisions/0006-keys-and-sealing/) |
| <a id="audit-family"></a>**audit family** | The audit pieces: the emitter library in every actor, the audit transport, the writer, the witness, the indexer and the reader. Its pieces read their documents (the config kinds AuditLog, AuditWitnesses and AuditCatalogue) through the data port, like the actors of every other family; the blob, the transport and the index are their own ports. | [ADR 0002](/decisions/0002-families-of-actors/#the-four-families), [ADR 0028](/decisions/0028-audit-pieces/) |
| <a id="foundation"></a>**foundation** | The data and keys families (store@, exporter@, key@): what every installation runs, whatever else runs above it. Its binaries do not change with the modules. A grouping, not a fifth family. | [ADR 0002](/decisions/0002-families-of-actors/#the-foundation-and-the-modules) |
| <a id="module"></a>**module** | A set of actors on top of the foundation, bringing its own kinds and key purposes into the registries: identity (the work actors other than quota, the adapters included), audit (the audit pieces) and quota (quota). An installation runs the foundation and the modules it needs, for example the foundation with the audit module only.<br>*Note:* Not the accounts module of a hub installation, and not the module part of a log id. | [ADR 0002](/decisions/0002-families-of-actors/#the-foundation-and-the-modules) |
| <a id="store"></a>**store@** `store@<boundary>` | The data family's holder of storage credentials. It serves the one generic store service to work actors on their data port, enforces the kind registry, and has exactly four ports downward, one per storage class: config source, secret source, durable and temp. It never seals or opens a value.<br>*Avoid:* state-owner; state port; config loader (of an actor); secrets port. | [ADR 0005](/decisions/0005-the-store/) |
| <a id="key"></a>**key@** `key@<boundary>` | The keys family's holder: it holds the card PIN or the KMS permission of one boundary and offers Seal, Open, Sign and Mac (a keyed hash) to callers whose grant and rules allow it. It caches opened data keys in memory, each with its own time to live.<br>*Avoid:* key-holder; keys driver (for the holder); key service (for key@). | [ADR 0006](/decisions/0006-keys-and-sealing/) |
| <a id="exporter"></a>**exporter@** `exporter@<boundary>` | The data family's second holder: it watches the store for kinds marked exportable, opens sealed values at key@ with its own grant, writes them to destinations outside sluis with its own destination credential, and audits each write. A full reconcile runs at start and daily.<br>*Avoid:* export port; export driver (for the holder). | [ADR 0009](/decisions/0009-export/) |
| <a id="port"></a>**port** | A named interface of a unit. A work actor has a data port (to store@), a keys port (to key@), an audit emit port, and the ports of its own job (an HTTP listener for entry only, provider APIs, outbound fetch). store@ has four ports downward, one per storage class; exporter@ has one per destination; key@ has one for its card or KMS.<br>*Avoid:* state port; lease port; secrets port; config-source port; export port; capability flag. | [ADR 0002](/decisions/0002-families-of-actors/#ports-of-a-work-actor), [ADR 0005](/decisions/0005-the-store/#drivers) |
| <a id="transport"></a>**transport** | How a call between two units travels on one installation: a Unix socket with the caller known by uid, a Lambda invoke with the caller known by its role, or in-cluster gRPC authenticated by a projected service-account token whose audience the callee checks. The steps and the checks are the same on every transport.<br>*Note:* Not the audit transport, which is the queue, spool or stream between the emitters and the writer. | [ADR 0003](/decisions/0003-units-transports-and-fusion/#transports) |
| <a id="unit"></a>**unit** | What an installation starts for one actor: a systemd unit with its own user on boards, a Lambda function, or a Kubernetes pod with its own service account. One actor per unit unless the installation fuses work actors.<br>*Avoid:* container (as the Kubernetes unit); process (as a unit). | [ADR 0003](/decisions/0003-units-transports-and-fusion/#units) |
| <a id="fusion"></a>**fusion** | An explicit installation choice to run several work actors in one unit. The store then applies the union of their rules to that unit. A holder is never fused with a work actor, and key@ never with entry.<br>*Avoid:* fusion rule (as a free choice). | [ADR 0003](/decisions/0003-units-transports-and-fusion/#fusion) |
| <a id="cell"></a>**cell** | On Kubernetes, one replica of each actor scheduled together on one node; cells are spread across nodes and zones, and in-cluster services prefer the local cell. | [ADR 0003](/decisions/0003-units-transports-and-fusion/#cells) |
| <a id="platform-piece"></a>**platform piece** | A program an installation runs that is not an actor of any family: the edge connector, the card service, the engine processes and the node agent `sluis-node`. | [ADR 0002](/decisions/0002-families-of-actors/#platform-pieces) |
| <a id="actor-registry"></a>**actor registry** | The file that names every actor, its family, language, placement, calls, egress hosts and key purposes. With the kind registry it generates every enforcement layer and the reference pages.<br>*Avoid:* permission manifest. | [ADR 0002](/decisions/0002-families-of-actors/#registries-generate-the-enforcement), [Actors](/reference/actors/) |
| <a id="console"></a>**console** | The work actor of the operator API and pages. It checks the caller's delegation and routes each write to the actor that owns the kind; it writes only two kinds itself, `Switch` and `LogLevelOverride`.<br>*Avoid:* admin API (as an actor); part of entry. | [ADR 0002](/decisions/0002-families-of-actors/#the-console), [ADR 0027](/decisions/0027-the-console/) |

## Category: Data

The data model: kinds, addresses, classes, treatment.

| Term | Meaning | Read more |
|---|---|---|
| <a id="kind"></a>**kind** | A typed resource declared in the kind registry: a Protobuf schema, a scope, one storage class, a treatment, a profile, its layers or links, its declared indexes, its rules and exactly one writer. Its name is PascalCase (`DataKeyWrap`); its address segment is the kebab-case form (`data-key-wrap`).<br>*Avoid:* record kind; record (for stored data); object. | [ADR 0004](/decisions/0004-the-data-model/#kinds), [Kinds](/reference/kinds/) |
| <a id="kind-registry"></a>**kind registry** | The compiled list of every kind. The store enforces it, the tests and generated reference pages read it, and a kind that is not in it cannot be read or written.<br>*Avoid:* schema annotations; permission manifest. | [ADR 0004](/decisions/0004-the-data-model/#kinds), [Kinds](/reference/kinds/), [Rules](/reference/rules/) |
| <a id="address"></a>**address** `<boundary>/<tenant | ->/<kind>/<id>` | Where one item of a kind lives: the boundary, the tenant or `-`, the kind and the id. The address space is flat, not a tree; there is no other scope.<br>*Avoid:* record key; path (for an address); prefix (as a scope). | [ADR 0004](/decisions/0004-the-data-model/#the-address) |
| <a id="id"></a>**id** | The last part of an address. Actor, module, client and quota names are parts of the id, never scopes. An id never contains personal data: it is random, or a keyed hash of a natural key. | [ADR 0004](/decisions/0004-the-data-model/#the-address) |
| <a id="scope"></a>**scope** | The dimensions that separate data: the boundary, always, and the tenant, only for durable and temp kinds. Nothing else is a scope.<br>*Avoid:* installation scope; actor scope; client scope. | [ADR 0004](/decisions/0004-the-data-model/#the-address) |
| <a id="storage-class"></a>**storage class** | Where a kind lives and who writes it; exactly one per kind. The four classes are config, secret, durable and temp.<br>*Avoid:* origin; store (for a class). | [ADR 0004](/decisions/0004-the-data-model/#storage-classes) |
| <a id="config"></a>**config** | The storage class of read-only settings: signed documents from a file, a ConfigMap or AWS AppConfig, written by IaC or the publishing pipeline outside sluis. sluis never writes config. No tenant dimension.<br>*Avoid:* declared configuration; authority (as a class); install file. | [ADR 0004](/decisions/0004-the-data-model/#storage-classes), [ADR 0005](/decisions/0005-the-store/#configuration-loading) |
| <a id="secret"></a>**secret** | The storage class of read-only secrets: values from a systemd credential or AWS SSM, written by IaC. No tenant dimension. A secret that sluis generates or receives is not this class: it is sealed or hashed durable data.<br>*Avoid:* secrets port; sealed-state; vault. | [ADR 0004](/decisions/0004-the-data-model/#storage-classes) |
| <a id="durable"></a>**durable** | The storage class of read-write data that must survive: written by exactly one actor through the store, and backed up when it is authoritative. A time to live may be a field.<br>*Avoid:* state; issued durable; operator-set. | [ADR 0004](/decisions/0004-the-data-model/#storage-classes) |
| <a id="temp"></a>**temp** | The storage class of read-write data that may be lost: losing it costs a sign-in or a retry, never data. A time to live is mandatory. Never backed up.<br>*Avoid:* ephemeral state; cache (as a class). | [ADR 0004](/decisions/0004-the-data-model/#storage-classes) |
| <a id="built-in"></a>**built-in** | What the binary carries: defaults, hard limits, predefined policies and closed value sets such as the allowance modes. It is not a storage class and changes only with a release.<br>*Avoid:* schema default; floor in code (for all built-ins). | [ADR 0004](/decisions/0004-the-data-model/#built-in) |
| <a id="authoritative-kind"></a>**authoritative kind** | A durable kind that nothing else can recreate. Only authoritative kinds are backed up.<br>*Avoid:* origin issued. | [ADR 0010](/decisions/0010-backup-and-recovery/#what-the-archive-holds) |
| <a id="treatment"></a>**treatment** | How the store keeps a kind's value: hashed, sealed or plain, declared per kind. Sealed is the default.<br>*Avoid:* sensitivity; every value is encrypted. | [ADR 0004](/decisions/0004-the-data-model/#treatment) |
| <a id="hashed"></a>**hashed** | Treatment of a compare-only secret, such as a session id, a refresh token, a code or a generated client secret: only its hash is stored, it never reaches key@ and it is never read back. | [ADR 0004](/decisions/0004-the-data-model/#treatment) |
| <a id="sealed"></a>**sealed** | Treatment of a value that must be read back, such as a provider token or personal data: the actor seals it at key@ before writing, the store keeps the ciphertext, and only an actor with a grant can open it.<br>*Avoid:* encrypted in the port library; sealed secret. | [ADR 0004](/decisions/0004-the-data-model/#treatment), [ADR 0006](/decisions/0006-keys-and-sealing/#seal-and-open) |
| <a id="plain"></a>**plain** | Treatment of a value that is neither secret nor personal, such as a switch, a link or a counter: stored as it is. | [ADR 0004](/decisions/0004-the-data-model/#treatment) |
| <a id="one-writer-per-kind"></a>**one writer per kind** | Every durable and temp kind has exactly one writing actor, named in the registry; the store refuses any other. Config and secret kinds have one writer outside sluis: IaC or the publishing pipeline.<br>*Note:* Three kinds are declared self-scoped (Lease, ReplayGuard, SpentGrant): the id starts with the writing actor's name and the store lets each listed actor write only ids under its own name, so one writer per item still holds. The other named exception is the restore command of store@, which writes back the kinds it restores. | [ADR 0004](/decisions/0004-the-data-model/#one-writer-per-kind) |
| <a id="rule"></a>**rule** | One line of the registry: an actor may use a verb on a kind. The store checks the rule on every call, before it touches data.<br>*Avoid:* ACL; manifest entry. | [ADR 0005](/decisions/0005-the-store/#rules), [Rules](/reference/rules/) |
| <a id="verb"></a>**verb** | An operation on a kind: get, list, create, update, delete, apply, or watch. | [ADR 0005](/decisions/0005-the-store/#the-store-api) |
| <a id="linked-kinds"></a>**linked kinds** | Separate kinds that refer to each other by id, each in exactly one class, such as an app (config), its client secret (secret), a connection per tenant (durable) and an install in progress (temp). The store does not join them. | [ADR 0004](/decisions/0004-the-data-model/#layered-and-linked-kinds) |
| <a id="backup"></a>**backup** | A logical archive of the authoritative kinds, read through the store. Sealed values stay sealed, and the data key wraps are included. The archive is encrypted with AES-256-GCM under an archive key of its own, wrapped for the restore role and for an offline recipient.<br>*Avoid:* snapshot (for an archive); dump.<br>*Note:* A snapshot is the loaded config set of store@, not a backup. | [ADR 0010](/decisions/0010-backup-and-recovery/#what-the-archive-holds), [Data](/concepts/data/) |

## Category: Layers

Profiles, layers and how layered values combine.

| Term | Meaning | Read more |
|---|---|---|
| <a id="profile"></a>**profile** | Which layers may set a kind's value: Fixed, Operable or Tenant-adjustable. | [ADR 0004](/decisions/0004-the-data-model/#profiles) |
| <a id="fixed"></a>**Fixed** | The profile of settings with no write path at run time: built-in plus config. Change needs review and signature. Examples: installation shape, trust, key plan, tunables, login domains, upstreams made by hand or IaC. | [ADR 0004](/decisions/0004-the-data-model/#profiles) |
| <a id="operable"></a>**Operable** | The profile of settings an operator writes at run time, on top of built-in and config. It may be boundary-scoped or tenant-scoped (for example a hold on one person or tenant): observability, switches, retention and holds, upstreams made through a UI flow.<br>*Avoid:* operator-set. | [ADR 0004](/decisions/0004-the-data-model/#profiles) |
| <a id="tenant-adjustable"></a>**Tenant-adjustable** | The profile of settings written by a tenant admin, or by a product for its tenant, inside bounds declared in config, only in its own tenant and with a sealed grant: security limits, sign-in requirements, policies, clients, branding and the allowance.<br>*Avoid:* issued instance; tenant override. | [ADR 0004](/decisions/0004-the-data-model/#profiles) |
| <a id="layer"></a>**layer** | One source of a setting's value, lowest first: built-in, config, operator (at run time), tenant. All four apply to policies only; every other kind uses a subset.<br>*Note:* Not an isolation layer (retired) and not a Lambda layer (a packaging term). | [ADR 0004](/decisions/0004-the-data-model/#layers-and-the-direction-rule) |
| <a id="direction-rule"></a>**direction rule** | A higher layer may tighten freely; it may loosen only as far as the layer below allows, and a run-time loosening carries an expiry. The store checks it when the value is written.<br>*Avoid:* tighten-only (as the whole rule); precedence. | [ADR 0004](/decisions/0004-the-data-model/#layers-and-the-direction-rule), [Principles](/principles/) |
| <a id="tighten"></a>**tighten** | To change a setting so that less can happen (shorter lifetime, stricter sign-in, a forbid, a pause). A tightening takes effect at once and is durable. | [ADR 0004](/decisions/0004-the-data-model/#layers-and-the-direction-rule) |
| <a id="loosen"></a>**loosen** | To change a setting so that more can happen than the layer below yields (a longer lifetime, debug logging, a break-glass link). Allowed only as far as the layer below permits; at run time it expires. | [ADR 0004](/decisions/0004-the-data-model/#layers-and-the-direction-rule) |
| <a id="layered-kind"></a>**layered kind** | A setting split into one kind per layer, each in its own class. The store composes the layers into one effective value with its provenance, and checks the direction rule on every write. | [ADR 0004](/decisions/0004-the-data-model/#layered-and-linked-kinds) |
| <a id="combine-rule"></a>**combine rule** | How the store composes a layered kind: union for policies, where a Cedar forbid anywhere wins; shortest wins for lifetimes; intersection for sign-in methods; the unexpired override wins for log levels; the most specific wins for branding. | [ADR 0004](/decisions/0004-the-data-model/#layered-and-linked-kinds) |
| <a id="provenance"></a>**provenance** | What a read of a layered kind returns beside the value: which layer set each field, at which version.<br>*Avoid:* origin of an effective value. | [ADR 0005](/decisions/0005-the-store/#the-store-api) |
| <a id="bound"></a>**bound** | A limit declared in config (or built in) that a higher layer may not cross, such as a client template's allowed redirect hosts or a cap on a lifetime.<br>*Avoid:* slot (of a template). | [ADR 0004](/decisions/0004-the-data-model/#profiles) |

## Category: Store

The store: its API, drivers, engines and configuration loading.

| Term | Meaning | Read more |
|---|---|---|
| <a id="driver"></a>**driver** | A separate binary behind one port of a holder, private to its owner (store@, key@ or exporter@; key@'s card and KMS driver included): only the owner can open its socket. Each port has one contract and one CLI (`serve`, `check`, `version`, `conformance`). On Lambda a driver is an extension in the holder's function; on Kubernetes a native sidecar container in the holder's pod.<br>*Avoid:* per-actor driver; mediating driver; shared driver instance. | [ADR 0005](/decisions/0005-the-store/#drivers) |
| <a id="declared-index"></a>**declared index** | A lookup a kind declares in the registry, besides listing by tenant. A new question is a new reviewed index; there is no query language. | [ADR 0005](/decisions/0005-the-store/#the-store-api) |
| <a id="store-service"></a>**store service** | The one generic ConnectRPC service store@ serves on the data port: Get, List, Write and Watch, each carrying a kind name and bytes. The store decodes and validates against the kind registry and applies the kind's rules. There is no query language and no SQL.<br>*Avoid:* state service; one generated service per kind. | [ADR 0005](/decisions/0005-the-store/#the-store-api), [Store api](/reference/store-api/) |
| <a id="typed-client"></a>**typed client** | The client library an actor uses: `store.Client[T Kind]` in Go, `Store<K: Kind>` over `trait Kind` in Rust. Typed upward, generic on the wire.<br>*Avoid:* port library. | [ADR 0005](/decisions/0005-the-store/#typed-clients) |
| <a id="item"></a>**item** | What a driver sees: a key, a version, bytes, a time to live and index entries. A driver never knows what a kind means.<br>*Avoid:* record. | [ADR 0005](/decisions/0005-the-store/#drivers), [Store api](/reference/store-api/) |
| <a id="version"></a>**version** | The number the store sets on each item: 1 at create, plus 1 at each change. An update names the version it read (`if_version`); for a lease the version is the fencing token.<br>*Avoid:* revision. | [ADR 0005](/decisions/0005-the-store/#the-store-api) |
| <a id="watch"></a>**watch** | A verb that streams the changes of a kind from a resume point. Pushed on boards and Kubernetes; on Lambda a reader re-reads with an ETag instead.<br>*Avoid:* change feed; subscription. | [ADR 0005](/decisions/0005-the-store/#watch-and-the-resume-point) |
