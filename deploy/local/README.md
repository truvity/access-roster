# The local installation

Docker Compose on one workstation ([docs/runtimes/local.md](../../docs/runtimes/local.md)). Run it inside devbox, from the
repository root:

```bash
set -a; . "$SLUIS_BUILD_DIR/run.env"; set +a      # SLUIS_UPSTREAM_TARGET, SLUIS_KEYCLOAK_SECRETS or SLUIS_BUILD_DIR
devbox run -- just local-up                        # build, make the state, start, wait for healthy
devbox run -- just local-status                    # each service with its uid, state and health
devbox run -- just local-smoke-tamper              # store@ refuses a changed signed document
devbox run -- just local-logs store key
devbox run -- just local-down                      # remove the containers, the volumes and the state of the run
```

The person (M2), after `local-up`: `devbox run -- just local-login-headless` signs alice in with the real `sluis login`, and
`devbox run -- just local-person-smoke` runs the whole path: login, `sluis token --audience example-app`, the claims of
both tokens, the audit records of every step, and `sluis audit verify`. The harness fills in the identity provider's form
and computes the one-time password (`tools/harness/kclogin`); the CLI reaches the forwarder through a CONNECT proxy of the
test process, so no hosts file is needed. The identity provider's client for sluis must not add `session_state` to the
authorization response (entry's callback takes the closed list of RFC 6749 and RFC 9207 only).

A second project on one machine sets `COMPOSE_PROJECT_NAME`, `SLUIS_LOCAL_PORT` and `SLUIS_LOCAL_TAG` (the tag of its images),
and `SLUIS_LOCAL_SUBNET` where the firewall lets only some subnets reach the upstream; the first project is left alone.

| File | What it is |
|---|---|
| `compose.yaml`, `init.sh` | Generated by `just compose-gen` from the registries (`tools/gen/compose`). A golden test fails while they differ. |
| `Dockerfile` | One image for every executable: a static binary on distroless static (decision D-9). |
| `Dockerfile.rqlite` | The pinned rqlite release, one node. |
| `Caddyfile` | The forwarder: ends TLS for `sluis.dev.local.test` and forwards to `entry`'s socket. |
| `build.sh` | Builds the executables for this machine into `dist/local/bin`. |
| `local.sh` | `up`, `down`, `status`, `logs` and `tamper`. |

The state of a run is below `.cache/local`: the harness CA and the forwarder's leaf (`tools/harness/ca`), the publisher key,
the signed config documents and the bootstrap file that pins the key (`tools/harness/sign-config`), and the credentials.
None of it is in the repository, and `local-down` deletes it. The upstream's address and its client secret come from the
environment (`SLUIS_UPSTREAM_TARGET`, `SLUIS_KEYCLOAK_SECRETS`); the Compose file names neither.

Reach the issuer from the workstation with the harness CA and a name mapping:

```bash
curl --cacert .cache/local/ca/ca.pem --resolve sluis.dev.local.test:8443:127.0.0.1 \
  https://sluis.dev.local.test:8443/.well-known/openid-configuration
```

## Layout

- **Uids.** Every container runs as `user: uid:uid` of the registry (61000 + ordinal). The group of a driver's owner-side
  directory is the owner's uid plus 500; a caller joins the groups of the actors it may call (`group_add`).
- **Sockets.** A volume for each socket directory of PLAN.md "Socket layout", mounted into the owner read-write and into a
  caller read-only. `key@` has one volume per caller, and a caller mounts its own alone.
- **Network.** Every container has none, except the forwarder (a published loopback port) and the adapter, which shares the
  namespace of a `socat` sidecar that forwards `127.0.0.1:8180` to the upstream, because `iss` follows the host (D-11).
  The rqlite drivers share the engine's namespace.
- **`entry` has no `check` command,** so its health is the forwarder's probe of the discovery document through it.
